# WannaRap 启动与验收

## 环境

安装 Node.js **22.17 或更高版本**（建议使用 Node 22/24 LTS）。需要 npm。SQLite 使用 Node 内置模块，不需要安装数据库或 Docker。Node 22 可能显示 SQLite 实验性提示，不影响本版运行。

在终端进入本仓库根目录，即有 `package.json` 的 `wannarap` 文件夹。

## 开发模式

```sh
npm install
npm run dev
```

打开 http://127.0.0.1:3001 。前端和 API 由同一服务提供。命令会先构建，再同时监听前端与后端修改；前端重新构建完成后手动刷新浏览器，后端修改自动重启。Ctrl+C 停止。

Windows PowerShell 如果阻止执行 npm.ps1，请将命令里的 `npm` 替换为 `npm.cmd`，无需修改系统执行策略。

开发模式不需要代理。如果在 `.env` 修改 PORT，浏览器也使用对应端口。默认采用构建监听而非热更新，兼容当前受限 Windows 环境；没有额外的 5173 服务。

## 构建后运行

```sh
npm run build
npm start
```

打开 http://127.0.0.1:3001 。此模式由后端同时提供前端页面与 API，适合本机体验。先完成构建；修改前端后需要重新构建。

## 启用真实 AI（选填）

把根目录 `.env.example` 复制为 `.env`：

```powershell
Copy-Item .env.example .env
```

在 `.env` 中填写：

```dotenv
OPENAI_API_KEY=你自己的API密钥
OPENAI_MODEL=gpt-4.1-mini
```

模型可以改为你的账号可调用且支持 Responses API 的模型。重启服务后，页面显示「AI 已配置」。该状态表示已配置密钥；实际服务是否可用以请求结果为准。密钥只由后端读取，不要加 VITE_ 前缀，也不要提交 `.env`。

未配置密钥也能运行所有非 AI 功能；聊天和写词明确显示「演示模式」并返回固定练习模板。真实请求失败会显示错误，不会伪造模型回复。

## 首次体验

1. 点击左侧「加入 WannaRap」→「创建账号」，自行设置用户名和至少 8 位密码；没有内置共享账户。
2. 在发现音乐中筛选歌曲并收藏，个人空间可以查看收藏。
3. 在 Rap 伙伴中发送消息；切换页面或刷新后历史保留。
4. 在写词工作台输入歌词，点击「保存草稿」。修改未保存时不要离开页面。
5. 在练习室开始节拍器，至少练习 5 秒，结束后保存记录。
6. 选择本地 MP3/WAV 音频，在底部播放器回放；文件留在本机。
7. 发布一篇社区作品，测试点赞和评论；可选填你拥有权利且公开可访问的 HTTPS 音频直链。不能直接粘贴需要登录的网盘分享页充当音频。

## 检查

```sh
npm run check
npm test
npm run build
```

测试使用临时/内存数据库，不修改你的正式数据。涵盖注册登录、会话失效、账号隔离、推荐筛选、草稿、社区、练习、输入校验、AI 故障和持久化。

## 数据与备份

数据保存在 `database/wannarap.sqlite`（首次启动创建），被 Git 忽略。停止服务后备份该文件；若还存在同名 `-wal`、`-shm` 文件，应一起保存。不要在服务运行时直接删除或替换数据库。

## 常见问题

- `node:sqlite` 不可用：检查 `node --version`，升级至符合要求的 Node 版本。
- 页面无法连接 API：确认终端显示 WannaRap 服务地址，默认 3001；不要使用 5173。
- 端口占用：先停止另一份 WannaRap 进程，不要同时运行开发模式与生产模式的默认后端。
- AI 失败：检查服务端密钥、模型权限和联网情况；本版 45 秒超时。
- 音频无法播放：尝试浏览器支持的 MP3 或 WAV；外部音频需要直链和可访问的服务器。外部音乐平台的可用性取决于网络与地区。
